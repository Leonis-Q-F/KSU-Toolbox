# 支持范围与故障处理

## 当前支持

- Windows x64、Python 3.10+ 源码运行或便携 EXE。
- 小米、红米、POCO 的已解锁 ARM64 A/B 设备，使用 v4 `init_boot`。
- 当前系统完整卡刷包：本地 ZIP 或支持 Range 读取的 HTTPS URL。
- 线刷包：本地 TGZ、TAR、TAR.GZ、ZIP 或解压目录，含同一包目录下的 `misc.txt` 和 `images/init_boot.img`。
- 官方 KernelSU LKM 已验证布局，含可选的 v3.3.1 默认 `ksu_config`（`bundled=1`）。

当前不支持增量 OTA、旧版本固件、独立 IMG、需要修补 boot 的设备、Magisk、APatch、GKI。支持条件不代表每台机型都已真实刷写验证。

## 常见情况

| 显示内容 | 处理 |
|---|---|
| 找不到 adb.exe | 1.1.1 已内置工具，请完整解压整个包而非只复制 EXE；也可传 `--tools` |
| 未连接 / unauthorized | 手机正常开机、启用 USB 调试、解锁并允许此电脑 |
| 版本不符 | 提供手机当前版本的完整包；不要用旧包凑版本 |
| 多个新修补文件 | 重新运行，只生成一个新的修补结果 |
| 未找到新修补文件 | 不会使用旧路径；请修补本次传入的原厂文件并保留新文件名 |
| 不支持的修补布局 / 配置 | 保留日志，使用官方默认修补配置；不要绕过检查 |
| Fastboot 未连接 | 检查 USB 驱动、线缆、接口；原厂镜像仍在备份目录 |
| 刷写失败 | 保留现场，不换槽位、不盲目重试；根据本次恢复说明操作 |
| 开机验证超时 | 先观察手机；可能只是启动耗时或 USB 授权问题 |

## 恢复与日志

每次提取保留 `init_boot.img`、校验结果和 `恢复说明.txt`。恢复命令只适用于本次记录的同一系统与槽位。系统升级后不可直接使用旧会话恢复镜像。

`session.json` 和日志包含序列号、来源链接与本地路径，报告问题前需脱敏。不要公开上传整份备份目录。

## 验证边界

初始手动流程在 Xiaomi 15 (`dada`) 上成功；工具的 OTA 提取和旧包拒绝进行过实机只读验证。自动刷写路径通过模拟 USB 的完整流程测试，界面迭代没有重复刷写手机。未来版本、其他机型及修补格式需要各自验证。
